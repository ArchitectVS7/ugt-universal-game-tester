## Orchestrator protocol

1. **Check out** the first task with `status: TODO` whose `after:` tasks are all DONE. Set it `IN-PROGRESS`.
2. **Plan** — hand the coder the task block plus the pointers named in this intro. Nothing else.
3. **Code** — implement per the plan and the Standing constraints.
4. **Review** — check the diff against the task's **Accept** criteria.
5. On pass: run the gate, commit as `<ID>: <title>`, set `status: DONE`, update this file in the same commit. On fail: one fix round, then escalate, then halt.

**Gate (every task):** `python3 -m py_compile integrations/pond/*.py ugt/core/*.py` exits 0, **and** `python3 integrations/pond/verify_round1.py` still reports MET with no regression in its check count (R1 is the known-green rung and must never break while R2 is edited). Tasks that change R2 additionally run `python3 integrations/pond/verify_round2.py` and record its score in the delivery note. the-pond M7 has landed, so **R2 is expected to improve markedly** (several formerly-blocked modes now pass); the goal is that every check executes game code and its verdict reflects the game's real current state. Record the measured score; never tune a check to hit a number.

**Standing constraints** (the reviewer enforces on every task):
- **A gate check must execute game code.** No check may assert a conclusion from source-reading alone; if a fact cannot be measured over the wire, it is a `finding`, not a `check`. This is the defect this whole list exists to repair.
- **No vacuous passes.** Every assertion must be able to fail. Comparing a value to itself, asserting on an empty collection, or asserting a boolean while the detail string claims something stronger is prohibited.
- **Never widen a denominator to look better, never narrow one to hide a gap.** If a check changes category, say so in the delivery note with the before/after tally.
- **Findings text must match measured evidence.** A finding may not assert a mechanism the run did not observe (this is how PC-15's false diagnosis shipped).
- **A green check must prove the fix, not paper over the tester.** Now that the game modes are reachable, a check that passes must pass because the game *works*, verified over the wire — not because the assertion was weakened.
- **Never reimplement game logic in the tester** (repo `CLAUDE.md`) — read state over the wire.
